# POST /jobs Implementation Plan

> **For agentic workers:** Execute inline with the available executing-plans skill, task by task, using the checkboxes below. No delegation or application implementation is authorized by this documentation-only request.

**Goal:** Persist POST /jobs before HTTP 202, then summarize asynchronously through an OpenAI Responses adapter with durable outcomes.

**Architecture:** Route → validation → controller → submission service → SQLite repository. A single background loop calls a processing service using a fakeable provider interface; only the adapter imports the SDK. Existing AppError definitions and error middleware remain the HTTP boundary.

**Tech Stack:** Node 22.20+ (22.x), TypeScript strict, pnpm 11.21.0, Express 5, better-sqlite3, official `openai` SDK, Vitest, Docker Compose.

**Spec:** [POST jobs spec](../specs/2026-09-08-post-jobs-design.md). This plan is a proposal for review, not implementation already performed.

## Global constraints

- Responses API only; preserve API_KEY, BASE_URL, MODEL. No Chat Completions fallback.
- Persist before returning 202; no provider calls on submission path.
- MAX_ATTEMPTS=1, single worker/process; no implicit SDK retries.
- Never log secrets/prompts/raw SDK objects; never put .env in image.
- No database migrations needed for this scope; use current jobs columns.
- No GET /jobs/:id, callback sending, retries, idempotency or multiple replicas in this plan.
- Keep source instructions only in root AGENTS.md; user-selected src/error layout takes precedence over its older errors.ts wording.
- Run automated checks with fakes; no billable network calls.

Public types to define once and reuse (no duplicate DTOs in controllers):

```ts
export interface SubmitJobInput {
  text: string;
  callbackUrl?: string;
}
export interface Usage {
  inputTokens: number;
  outputTokens: number;
}
export interface SummaryResult {
  summary: string;
  usage: Usage;
}
export type JobStatus = 'queued' | 'running' | 'succeeded' | 'failed' | 'dead';
export interface JobRow {
  id: string;
  text: string;
  callbackUrl: string | null;
  status: JobStatus;
  attempts: number;
  summary: string | null;
  errorCode: string | null;
  errorMessage: string | null;
  inputTokens: number;
  outputTokens: number;
  costMicrousd: number;
  createdAt: number;
  updatedAt: number;
}
export interface JobOutcome {
  status: 'succeeded' | 'failed' | 'dead';
  summary: string | null;
  errorCode: string | null;
  errorMessage: string | null;
  usage: Usage;
}
export interface JobRepository {
  insert(job: JobRow): void;
  findById(id: string): JobRow | undefined;
  claimNext(now: number): JobRow | undefined;
  finish(id: string, attempt: number, outcome: JobOutcome, now: number): void;
  recoverInterrupted(now: number): number;
}
export interface SummarizationProvider {
  summarize(text: string): Promise<SummaryResult>;
}
```

`ProviderFailure extends AppError` in ai/provider.ts carries `retryable: boolean`,
`usage?: Usage`, `retryAfterMs?: number`; constructor takes ErrorDefinition plus
metadata and cause. Do not redefine codes outside src/error/definition. Error normalization
occurs in adapter; terminal/retry policy remains processing service responsibility.

## Task 5 — Atomic processing and interrupted-job recovery

**Files:** jobs/repository.ts, processing-service.ts; `tests/jobs-processing.test.ts`.

**Interfaces:** `createProcessingService(repository, provider, now).processNext(): Promise<boolean>`;
true means an attempt was processed, false means no queued job. Throws on persistence failure.

- [ ] Write transaction tests: only one claim for the same job across two file-backed
      connections; attempts increment once, conditional finish cannot double-charge.
- [ ] Implement claim selection and update in one immediate transaction:

```sql
SELECT * FROM jobs WHERE status = 'queued' ORDER BY created_at, id LIMIT 1;
UPDATE jobs SET status='running', attempts=attempts+1, updated_at=@now
WHERE id=@id AND status='queued';
```

Require changes=1 before returning a claimed row. Network calls run after commit.

- [ ] Implement outcome write conditional on id + running + claimed attempt; require
      changes=1, otherwise throw an AppError rather than silently ignoring a lost claim.

```sql
UPDATE jobs SET status=@status, summary=@summary, error_code=@errorCode,
 error_message=@errorMessage, input_tokens=input_tokens+@inputTokens,
 output_tokens=output_tokens+@outputTokens,
 cost_microusd=cost_microusd+@costMicrousd, updated_at=@now
WHERE id=@id AND status='running' AND attempts=@attempt;
```

Service computes `costMicrousd=3*inputTokens+15*outputTokens`, validates safe integer
and accumulated result safety before commit. No cost calculation in controller.

- [ ] Implement processNext: claim → await provider → build outcome → finish. Catch only
      the provider call for classification; put repository.finish outside that catch so a
      DB failure cannot be misreported as model failure or trigger a second call.
- [ ] Assert success usage (100 input,20 output) persists 600 micro-USD; permanent failure
      becomes failed, transient becomes dead at attempt1, unknown becomes dead PROVIDER_0006.
      Preserve any valid failure.usage; absent usage adds zero reported units.
- [ ] Implement recovery before worker start:

```sql
UPDATE jobs SET status='dead', error_code='PROVIDER_0005',
 error_message='Processing was interrupted', updated_at=@now WHERE status='running';
```

Use provider definition's safe message via parameters in final code; preserve usage/attempts.

- [ ] Test queued survives close/reopen and completes; interrupted running becomes dead;
      provider success followed by DB failure rejects processing and is not called twice.
      Run repository/processing tests and existing SQLite tests.
